## 一、项目概述

### 1.1 项目背景

本项目为 `crm-new-project` 前端应用提供后端 RESTful API 服务，采用 Node.js + Express + TypeScript 技术栈构建。主要实现用户认证（登录、获取用户信息）功能，并对接已创建的 `crm_system` 数据库。

### 1.2 项目目标

- 为前端 Vue 3 应用提供标准化的 REST API
- 实现用户登录认证功能（JWT Token）
- 建立可扩展的后端服务架构
- 支持后续功能模块的快速迭代

## 五、替代方案分析

### 5.1 Web 框架对比

| 框架 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **Express** (当前) | 简洁灵活、中间件丰富、社区成熟 | 缺乏结构化、需手动组织 | 快速开发、中小型项目 |
| **NestJS** | 模块化、装饰器、依赖注入、TypeORM 集成 | 学习曲线陡峭、重量级 | 企业级应用、微服务 |
| **Fastify** | 性能极高、Schema 验证、插件系统 | 生态较新、插件较少 | 高性能 API、IO 密集型 |
| **Koa** | 洋葱模型、轻量、异步流程控制 | 中间件需自行适配、文档较少 | 定制化需求、中间件开发 |

**建议改进**：如果项目规模扩大，建议迁移到 **NestJS**，它提供了：
- 内置依赖注入容器
- 模块化组织结构
- 自动生成 OpenAPI 文档
- 更好的类型安全
- 内置测试框架支持

### 5.2 数据库 ORM 对比

| ORM | 优点 | 缺点 | 适用场景 |
|-----|------|------|----------|
| **mysql2** (当前) | 轻量、性能高、SQL 直观 | 需手写 SQL、缺乏类型安全 | 简单项目、性能敏感 |
| **Prisma** | 类型安全、自动迁移、可视化 | 生态较新、复杂查询稍慢 | TypeScript 项目、快速开发 |
| **TypeORM** | 功能丰富、装饰器、迁移工具 | 性能一般、文档不完善 | 复杂业务、中大型项目 |
| **Sequelize** | 久经考验、社区活跃、关联丰富 | 回调地狱历史、配置繁琐 | 老项目、关联复杂 |

**建议改进**：使用 **Prisma** 可获得：
- 编译时类型检查
- 自动生成数据库迁移
- 直观的 API 设计
- 更好的性能优化空间

### 5.3 认证方案对比

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **JWT** (当前) | 无状态、可扩展、跨域友好 | 无法主动失效、存储限制 | 单体应用、微服务 |
| **Session** | 可控制失效、简单直观 | 占用服务器内存、分布式复杂 | 传统 Web、不限存储 |
| **OAuth2 + SSO** | 第三方登录、集中认证 | 实现复杂、需维护服务器 | 多系统统一认证 |
| **Passport.js** | 多策略支持、社区丰富 | 配置繁琐、文档分散 | 需要多种登录方式 |

**建议改进**：当前 JWT 方案适合当前场景，但建议增加：
- Token 黑名单机制（Redis 存储）
- Refresh Token 定期轮换
- 敏感操作二次验证

### 5.5 生产环境建议

| 组件 | 当前 | 建议改进 |
|------|------|----------|
| **进程管理** | 手动 node | PM2 / Docker |
| **日志** | console.log | Winston / Pino |
| **配置** | .env 文件 | Consul / Nacos 配置中心 |
| **缓存** | 无 | Redis (Token 黑名单、热点数据) |
| **监控** | 无 | Prometheus + Grafana |
| **API 文档** | 无 | Swagger / OpenAPI |
| **安全** | 基础 | Helmet + Rate Limiting + CORS 细化 |

bcrypt 是原生 C++ addon，安装时依赖 postinstall 脚本执行 node-gyp rebuild 来编译 .node 二进制文件。但 pnpm 默认出于安全考虑会跳过所有包的构建脚本（ignore-scripts=true），导致 bcrypt 编译被跳过。
解决方案（三选一）：

方案	命令	说明
1. 临时放行	pnpm install --ignore-scripts=false	最快，仅本次生效
2. 安装后手动重建	pnpm install && pnpm rebuild bcrypt	更安全，只重建 bcrypt
3. 换用纯 JS 替代	pnpm remove bcrypt && pnpm add bcryptjs	推荐，零原生依赖，跨平台无编译问题，API 完全兼容，只需把 require('bcrypt') 改成 require('bcryptjs')
